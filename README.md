# pi-loop

Pi 扩展：激活后无限自我迭代。

循环不会因为模型或进程的任何自身原因停止：模型说「做完了」、反问、请求确认、请求出错、运行被 Esc 中断、扩展重载、进程被强杀，都会自动继续。唯一停止方式是执行 `/loop-off` 或 `/loop-off-now`。

- 需要无人值守连续推进同一目标：从「安装」开始。
- 了解循环的完整行为：见「循环为什么停不下来」。
- 修改扩展代码：先读「关键认知」。

## 安装

pi-loop 的主体是单个 TypeScript 文件 `index.ts`。Pi 内置 TypeScript 加载，不需要编译；`@earendil-works/pi-coding-agent` 与 `@earendil-works/pi-tui` 由 Pi 宿主在运行时提供，不需要执行 `npm install`。

### 普通用户

推荐用 Pi 包安装，版本更新可用 `pi update --extensions` 统一处理：

```bash
# 用户级（写入 ~/.pi/agent/settings.json）
pi install git:github.com/jerryshell/pi-loop

# 项目级（写入 .pi/settings.json）
pi install -l git:github.com/jerryshell/pi-loop
```

卸载：

```bash
pi remove git:github.com/jerryshell/pi-loop
```

手动安装：从仓库检出目录复制 `index.ts`。

用户级安装（所有项目可用）：

```bash
mkdir -p ~/.pi/agent/extensions/pi-loop
cp index.ts ~/.pi/agent/extensions/pi-loop/index.ts
```

项目级安装（只对当前项目生效）：

```bash
mkdir -p .pi/extensions/pi-loop
cp index.ts .pi/extensions/pi-loop/index.ts
```

Windows 的用户级路径为 `%USERPROFILE%\.pi\agent\extensions\pi-loop\index.ts`。

放置完成后重启 Pi；已在会话中则执行 `/reload`。命令列表中出现 `/loop` 即加载成功。

不改动配置、只试用一次：

```bash
pi --extension /path/to/pi-loop
# 简写
pi -e /path/to/pi-loop
```

`--extension` 接受扩展文件，也接受包含 `index.ts` 的目录。

### 扩展开发者

```bash
git clone https://github.com/jerryshell/pi-loop
cd pi-loop
npm install        # 开发依赖：类型检查与代码工具
npm run check      # 类型检查 + oxlint + oxfmt 格式检查
pi -e .
```

代码检查用 oxlint（配置 `.oxlintrc.json`），代码格式化用 oxfmt（配置 `.oxfmtrc.json`）。日常用 `npm run format` 就地格式化，提交前用 `npm run check` 做总检查。

改动 `index.ts` 后，在 Pi 中执行 `/reload` 即可生效。Pi 会替换扩展运行时，循环状态从会话记录恢复，继续迭代。

把仓库目录链接到扩展目录，可省去手动复制，之后只需执行 `/reload`：

```bash
# macOS / Linux
ln -s "$(pwd)" ~/.pi/agent/extensions/pi-loop

# Windows（目录联接）
mklink /J "%USERPROFILE%\.pi\agent\extensions\pi-loop" "%CD%"
```

包清单：`package.json` 的 `pi.extensions` 声明入口 `index.ts`，宿主包放入 `peerDependencies`（`"*"`），`devDependencies` 只用于编辑器类型与 `npm run typecheck`。宿主提供的包不要放入 `dependencies`，避免绕过宿主的模块映射。

## 命令

| 命令            | 行为                                                                                 |
| --------------- | ------------------------------------------------------------------------------------ |
| `/loop [目标]`  | 激活循环。空闲时立即开始下一轮；运行中则在本轮结束时接管，带参数可随时更新长期目标。 |
| `/loop-off`     | 里程碑停止：当前轮自然结束后停止；空闲时立即停止。                                   |
| `/loop-off-now` | 立即停止：中止当前运行，取消所有待执行的重启，清除循环状态。                         |

轮数在同一会话内累计；停止后重新激活不会归零。

## 底部状态栏

| 显示                 | 含义                                             |
| -------------------- | ------------------------------------------------ |
| `∞ loop #12`         | 运行中，`#12` 为已开始的轮数                     |
| `∞ loop #12 ↻`       | 运行已结束，等待自动重新点火                     |
| `∞ loop #12 ⚠`       | 最近连续多轮没有工具调用，迭代指令已附加停滞警告 |
| `∞ loop #12 收尾中…` | 已执行 `/loop-off`，等待当前轮结束               |

## 循环为什么停不下来

| 触发情况                     | 处理                                                            |
| ---------------------------- | --------------------------------------------------------------- |
| 模型自然结束、反问、请求确认 | `agent_before_settle` 返回 `continue: true`，注入下一轮迭代指令 |
| 模型请求出错                 | 不停止；按 5 s → 10 s → … → 60 s 退避后继续，并要求先诊断错误   |
| 运行被 Esc 中断              | `agent_settled` 后自动重新点火                                  |
| 运行异常结束、边界无法继续   | `agent_settled` 后自动重新点火                                  |
| 看门狗发现「已激活但空闲」   | 每 15 s 检查一次，立即重新点火                                  |
| 扩展重载（`/reload`）        | 新运行时从会话记录恢复状态，自动继续                            |
| 进程退出、被强杀             | 用 `--continue` 恢复该会话时自动继续迭代                        |

重新点火的延迟从 1 s 起指数增加，封顶 30 s；每次运行成功启动后归零。

## 每轮注入的迭代指令

每轮开始时向模型注入指令，核心内容：

- 立即开始当前最高价值的下一步工作并直接动手；不征求许可、不复述计划、不以提问结束。
- 本轮必须有真实产出（文件修改、命令执行、验证结果）；纯文字回复不算迭代。
- 完成后自行验证（测试、构建、运行），简短记录结果和新发现，然后继续下一轮。
- 当前目标完成后，主动寻找下一个更高价值的改进点继续推进。
- 只有外部指令 `/loop-off` 或 `/loop-off-now` 才能结束循环；不自行收尾，也不询问是否继续。

附加提示按情况追加：连续无工具调用时追加停滞警告；上一轮出错时要求先诊断错误；上一轮被中断时要求从中断处继续。

上下文规则只有一条：激活时只保留最新一条迭代指令，循环关闭后全部移除。会话上下文不会随轮数持续膨胀，关闭后也不残留指令。

## 关键认知

修改代码前先读本节。以下契约是扩展对外行为的依据，违反任意一条都视为回归。

### 1. 停止条件只有外部显式指令

模型的一切自述都不算停止信号：完成、提问、请求确认、报错、被中断都只触发继续。循环只有三种阶段：`off`（关闭）、`running`（运行）、`stopping`（已执行 `/loop-off`，等待本轮里程碑）。

### 2. 四道点火机制分工覆盖

| 机制                  | 时机                        | 作用                                    |
| --------------------- | --------------------------- | --------------------------------------- |
| `agent_before_settle` | 模型即将自然结束            | 注入下一轮并返回 `continue: true`       |
| `agent_settled`       | 运行彻底结束（中断、异常）  | 延迟重新点火，带指数退避                |
| 看门狗                | 每 15 s                     | 阶段为 `running` 但运行已空闲时重新点火 |
| `session_start`       | 会话启动、`--continue` 恢复 | 读取会话记录恢复状态并续跑              |

四道机制可能同时命中，用 `runActive`、`restartArmed`、`pendingRestart` 三个标志互斥。改动其中一道必须检查其余三道是否会重复点火。

### 3. 上下文只保留最新一条迭代指令

`context` 钩子按轮裁剪：激活时保留最后一条，关闭后全部移除。这是长跑会话不膨胀、关闭后不污染对话的原因，不要改成普通消息。

### 4. 迭代是否真实由工具调用判定

`tool_execution_start` 置位 `usedToolThisRound`；一整轮没有任何工具调用时 `stallStreak` 加一，下一轮指令追加停滞警告。纯文字回复不算迭代。

### 5. 循环状态写入会话，进程内变量只是缓存

`phase`、`goal`、`iteration` 通过 `pi.appendEntry("pi-loop-state", ...)` 持久化到会话。跨进程恢复（`--continue`、强杀后重启）依赖它；只在内存里改状态会导致恢复后行为错乱。

### 6. 退避与延迟是防热循环的保险

- 模型请求错误：5 s → 10 s → … → 60 s 封顶。
- 重新点火：1 s 起，指数增加，30 s 封顶；运行成功启动后归零。
- 会话恢复：延迟 1.5 s 点火，避免抢占用户启动时提交的第一条消息。

### 7. 单文件、无构建、依赖宿主

只用宿主提供的 `@earendil-works/pi-coding-agent` 与 `@earendil-works/pi-tui`；不引入编译步骤，`pi -e .` 直接运行。新增第三方依赖前先确认宿主的提供清单（Pi 文档 `packages.md`）。

## 排查

| 现象                 | 先检查             | 处理                                                                 |
| -------------------- | ------------------ | -------------------------------------------------------------------- |
| 命令列表没有 `/loop` | 扩展是否加载       | 确认 `index.ts` 位于用户级或项目级扩展目录，执行 `/reload` 或重启 Pi |
| 状态栏没有 `∞ loop`  | 循环是否已激活     | 执行 `/loop`；状态栏只在激活后显示                                   |
| 状态栏停在 `↻`       | 是否处于退避延迟   | 等待重新点火，最长延迟 30 s                                          |
| 连续多轮没有工具调用 | 状态栏是否显示 `⚠` | 无需人工处理，迭代指令会附加停滞警告                                 |
